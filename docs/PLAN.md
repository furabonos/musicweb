# 기획서: 말로 만드는 재생목록 (가칭)

## 1. 한 줄 소개

검색창에 "Central Cee - Doja와 비슷한 곡 10개"처럼 말로 요청하면 재생목록을 만들어서 바로 틀어 주고, YouTube로 가져갈 수 있게 해 주는 PC 전용 공개 웹사이트.

## 2. 만드는 이유

- **쓰려고**: 곡 하나에서 시작해 취향에 맞는 재생목록을 빠르게 얻는다.
- **보여 주려고**: 사람이 신경 쓰지 않아도 돌아가고, 문제가 생기면 에이전트가 고쳐서 PR을 올리는 구조를 실제 서비스로 운영하고, 그 결과를 숫자로 공개한다.

## 3. 사용자와 범위

- 누구나 접속해서 쓰는 공개 서비스다.
- PC 웹만 지원한다. 모바일 화면은 고려하지 않는다.
- 로그인 없이: 둘러보기, 공유된 재생목록 보기와 재생, 현황판 보기
- 로그인하면: 재생목록 만들기 (비용과 남용 관리를 위해 로그인 필요)

## 4. 핵심 흐름

1. 검색창에 자연어로 요청한다.
2. 요청에서 기준 곡, 곡 수, 조건을 뽑는다.
3. 비슷한 곡으로 재생목록을 구성한다 (5번 추천 방식).
4. 결과를 보고 곡을 빼거나 바꾼다.
5. 사이트에서 바로 재생한다.
6. YouTube로 가져가거나 주소로 공유한다 (7번).

## 5. 추천 방식

곡 목록은 "어디서 틀 수 있는지"만 알려 준다. "무엇이 비슷한지"는 아래 재료에서 얻는다.

- **공개 음악 데이터**: 같이 듣는 곡, 비슷한 아티스트, 장르, 분위기 태그. 가장 믿을 만한 재료다.
- **곡 목록에 붙여 둔 정보**: 장르, 태그, 발매 연도, 아티스트. 조건으로 걸러 내고 가까운 곡을 고를 때 쓴다.
- **같이 담긴 곡**: 사용자들이 만든 재생목록에 함께 담긴 곡. 누가 담았는지 알 수 없게 횟수만 모은다.
- **AI의 음악 지식**: 장르, 스타일, 영향 관계. 최신 곡을 모르고 없는 곡을 지어낼 수 있다. 요청 때마다 쓰지 않고 보조로만 쓴다.

**비용 원칙**: 사용자가 늘어도 AI 비용이 거의 늘지 않게, 비슷한 곡은 미리 싸게 계산해 두고 요청 때는 조회만 한다.

- 아티스트마다 "비슷한 아티스트" 목록을 예약 작업으로 계산해 저장한다.
- 곡마다 장르·태그·연도를 숫자 묶음으로 바꿔 저장한다. 요청 때는 "비슷한 아티스트의 곡 중 기준 곡과 가까운 곡"을 조회로 뽑는다 (AI 호출 없음).
- 인기 아티스트의 곡 수천 개만 미리 계산하고, 나머지는 처음 요청될 때 계산해서 저장한다.
- 같은 요청과 같은 조건 조합의 결과는 저장해서 다시 쓴다.

추천 과정:

1. 요청 해석: 저장된 결과 → 규칙으로 해석 → (그래도 안 되면) AI 해석. 곡을 직접 검색해 고르고 곡 수·조건을 버튼으로 정하는 화면은 AI가 필요 없다
2. 후보 모으기: 미리 계산한 비슷한 아티스트의 곡 + 같이 듣는 곡 + 같이 담긴 곡
3. 걸러 내기: 곡 목록에 실제로 있는 곡만 남긴다
4. 고르고 정렬하기: 기준 곡과 가까운 정도로 고르고, 같은 아티스트가 몰리지 않게 섞는다. 곡마다 태그로 조립한 한 줄 이유를 붙인다. AI가 쓴 설명은 사용자가 요청할 때만 만든다
5. 결과 표시

"AI가 직접 고르는 방식"과 "미리 계산한 방식"은 시험 문제로 점수를 비교하고, 차이가 작으면 저렴한 쪽을 쓴다.

소리 자체를 분석하지는 않는다. 여기서 "비슷하다"는 같은 사람들이 좋아하고 같은 장르로 분류된다는 뜻이다.

나중에 더할 재료: 여러 공개 재생목록에 같이 들어 있는 곡(3단계), 사용자가 추천 결과에서 빼거나 남긴 기록.

## 6. 곡 목록 미리 쌓기

YouTube 검색 호출은 하루 한도가 작다. 요청마다 검색하지 않고 "곡 → YouTube 영상 ID" 목록을 미리 만들어 둔다.

- 저장하는 것: 아티스트, 곡 제목, 영상 ID, 장르, 발매 연도. 음원과 영상 파일은 저장하지 않는다.
- 채우는 방법: 예약 실행되는 프로그램이 YouTube 공식 API로 아티스트 공식 채널의 영상 목록을 받아 온다. 웹 페이지를 긁어 오지 않는다.
- 제목에서 곡 이름을 뽑는 일은 규칙으로 먼저 처리하고, 애매한 것만 AI에게 맡긴다.
- 매일 밤 자동으로: 새 곡 추가, 사용자가 찾은 아티스트 추가, 삭제되거나 비공개가 된 영상 확인.
- 곡 목록은 인기 아티스트로 시작해서 사용자가 찾는 아티스트를 추가하는 방식으로 키운다. 갱신은 최근에 조회된 곡 위주로 해서 읽기·쓰기 비용을 줄인다.
- 곡을 찾는 순서: 곡 목록 → 공개 음악 데이터에 등록된 YouTube 링크 → 검색(마지막 수단). 검색 결과는 곡 목록에 추가한다.
- **목록에 없는 곡 (인디, YouTube에만 있는 곡)**:
  - 검색창에 YouTube 주소를 넣으면 그 영상을 기준 곡으로 쓴다. 음악 영상이 아니면(YouTube가 알려 주는 분류 기준) 안내하고 멈춘다.
  - 이름으로만 요청했는데 목록에 없으면 YouTube 검색을 쓴다. 하루 검색 횟수 중 이 용도의 몫을 따로 정해 두고, 다 쓰면 링크 입력을 안내한다.
  - 음악 데이터에 없는 곡은 사용자가 아티스트·곡 이름을 확인하고, 그 이름으로 음악 데이터의 태그를 찾는다. YouTube 영상의 제목·설명·태그로 장르를 추론하지 않는다 (YouTube 정책이 영상 분류 추론을 금지).
  - 정보가 적은 곡은 화면에 "정확도가 낮을 수 있다"고 표시하고, 후보는 같은 채널의 다른 곡·태그가 가까운 곡·같이 담긴 곡에서 고른다.
  - 매일 밤 새로 들어온 곡을 음악 데이터와 다시 대조하고, 그 채널의 다른 곡을 수집한다.
- 공식 음원을 우선 연결한다. 라이브, 커버, 리믹스는 요청이 있을 때만 쓴다.
- 데이터 보관 기간과 갱신 주기는 YouTube API 약관에 맞춘다.

## 7. 재생과 내보내기

- **사이트에서 재생**: YouTube 공식 삽입 플레이어. 끝나면 다음 곡으로 넘어간다. 광고는 YouTube가 넣는 것이며 막지 않는다.
- **YouTube에서 열기** (기본): 로그인 없이 재생목록을 YouTube에서 열어 사용자가 직접 저장하는 링크. 이 링크 방식이 동작하는지 먼저 확인한다.
- **주소로 공유**: 만든 재생목록마다 공유 주소가 생긴다.
- **내 계정에 바로 넣기**: 사용자의 YouTube 계정에 재생목록을 직접 만든다. Google 앱 심사가 필요해서, 심사 전에는 등록한 테스트 사용자만 쓴다.
- 재생과 내보내기는 음악 서비스 인터페이스 뒤에 둔다. 처음 구현체는 YouTube 하나다.

## 8. 로그인

- Google 로그인만 지원한다. Firebase Authentication을 쓴다.
- 재생과 내보내기가 모두 YouTube 기반이라 Google 계정 하나로 충분하다. 다른 로그인 방식은 넣지 않는다.
- 로그인은 사이트 계정용이다. "내 계정에 바로 넣기"는 같은 Google 계정에 YouTube 재생목록 권한을 추가로 요청한다. 이 권한은 그 기능을 처음 쓸 때만 묻는다.

## 9. 로컬라이징

- 화면 언어는 브라우저 언어 설정을 먼저 보고, 없으면 접속 국가를 본다. 사용자가 바꿀 수 있고 선택을 기억한다.
- 처음 지원하는 언어는 한국어와 영어다. 문구는 언어 파일로 분리한다.
- AI가 쓰는 곡별 한 줄 이유도 화면 언어로 생성한다. 날짜와 숫자 표기도 언어에 맞춘다.

## 10. 자동 운영과 자동 수정

**스스로 돌아가는 부분**

- 매일 밤 곡 목록 갱신 (6번)
- 매일 시험 문제 실행과 현황판 수치 갱신

**스스로 고쳐지는 부분**

- 오류와 이상 결과를 감지하면 GitHub 이슈를 자동으로 만든다. 예: 제목 해석 실패, 깨진 영상 연결, 공식 음원이 아닌 영상 연결, 요청 해석 실패.
- 에이전트가 문제를 재현하는 테스트를 쓰고 수정 PR을 올린다.
- CI를 통과한 PR을 내가 확인하고 합친다. 자동 합침은 하지 않는다.
- PR 본문에는 쉬운 말 요약 3줄, 화면이 바뀌면 수정 전후 캡처, 테스트와 시험 문제 점수 변화, 직접 확인하는 방법을 넣는다.

**시험 문제**

- 곡 연결: 정답을 정해 둔 50곡으로 연결 정확도를 잰다.
- 추천: "이 곡을 넣으면 이런 곡들이 나와야 한다"는 문제로 추천 품질을 잰다.
- 매일, 그리고 CI에서 돌린다. 점수가 떨어지는 변경은 통과시키지 않는다.

## 11. 공개 현황판 (/status)

- 앱의 주요 동작을 처음부터 전부 기록한다: 요청 해석, 추천, 곡 연결, 사용자가 고친 내용, 외부 호출, 오류.
- 이슈, PR, CI, 되돌린 커밋 수치는 하루 한 번 GitHub에서 가져온다.
- 보여 주는 것
  - 서비스: 요청 해석 성공률, 없는 곡을 걸러 낸 수, 공식 음원 연결 정확도, 사용자가 뺀 곡의 비율, 추천 시험 점수
  - 곡 목록: 보유 곡 수, 어제 추가된 곡 수, 검색 없이 처리된 요청 비율, 오늘 남은 YouTube 호출 수
  - 자동 수정: 자동 이슈 수, PR 승인 비율과 거절 사유, 수정까지 걸린 시간, 되돌린 수정 비율, 최근 수정 10건과 PR 링크
  - 마지막 갱신 시각
- 숫자마다 계산 방법을 적고, 실패와 거절도 숨기지 않는다.
- 검색 문장, 재생목록 이름, 계정 정보는 현황판과 이슈에 드러내지 않는다.

### 운영 일지

숫자만으로는 AI가 무슨 일을 하는지 보이지 않는다. 현황판에 시간순 일지를 함께 보여 준다.

- 예약 작업의 시작과 끝, 처리한 양 (예: 아티스트 412명 확인, 새 곡 37개 추가)
- 발견한 문제와 자동으로 만든 이슈
- 에이전트가 올린 PR, CI 결과, 승인 또는 거절, 그 뒤의 시험 점수 변화
- 한도 도달, 작업 실패, 관리자가 켜고 끈 설정
- 항목마다 관련 이슈나 PR로 가는 링크를 단다.

## 12. 공개 서비스 운영

- **한도**: 재생목록 만들기 횟수를 사용자별로 하루 제한한다. API 호출과 AI 비용에는 서비스 전체 상한도 둔다. 사용자별 한도에 닿으면 안내하고 멈춘다.
- **절약 모드**: 서비스 AI 비용 상한에 닿으면 멈추지 않고 자동으로 절약 모드로 바뀐다. AI 해석과 AI 설명만 끄고 재생목록 만들기는 계속 동작한다. 화면에 간단히 안내하고 운영 일지에 기록한다. 관리자 화면의 긴급 정지(수동)와는 별개다.
- **AI 비용**: 요청 때마다 AI를 부르지 않는다(5번 비용 원칙). AI가 필요할 때는 가장 저렴한 모델부터 쓰고, 예약 작업의 AI 호출은 일괄 처리 할인을 쓴다. 서비스 서버의 AI 호출은 API 키로만 하고, 개인 구독 계정을 서비스에 연결하지 않는다.
- **개인정보 처리방침과 이용약관**: 수집하는 정보, 보관 기간, 삭제 방법을 적는다. Google 심사에도 필요하다.
- **계정과 데이터 삭제**: 사용자가 직접 지울 수 있다.
- **남용 방지**: 요청 횟수 제한, 자동화된 대량 요청 차단. 아무 영상 주소나 넣어 곡 추가를 반복시키지 못하게 링크 입력도 사용자별로 제한한다.
- **심사**: Google 앱 심사(내 계정에 바로 넣기)는 1단계에 신청한다. 할당량 증가 심사는 사용 기록이 쌓인 뒤 신청한다.

### 관리자 화면 (/admin)

운영자가 코드를 고치거나 데이터베이스를 직접 열지 않고 서비스를 관리하는 화면이다. 1단계는 꼭 필요한 것만 만든다.

- **긴급 정지**: 재생목록 만들기, 곡 목록 수집, 자동 이슈 생성을 각각 켜고 끈다. 비용이 폭주하거나 문제가 생겼을 때 쓴다.
- **한도 설정**: 사용자별 하루 한도, 서비스 전체 비용과 호출 상한을 바꾼다.
- **사용량 보기**: 오늘 쓴 YouTube 호출 수와 AI 비용, 한도까지 남은 양.
- **수집 대상 관리**: 수집할 아티스트를 추가하고 뺀다. 예약 작업의 최근 실행 결과를 보고 수동으로 다시 실행한다.
- **잘못된 연결 고치기**: 곡에 연결된 영상을 바꾸거나 막는다. 고친 내용은 시험 문제에 추가할 수 있다.
- **사용자 관리**: 남용하는 계정을 막는다. 내보내기 테스트 사용자를 관리한다.

보안:

- 관리자 Google 계정 목록에 있는 사람만 들어갈 수 있다. 권한 확인은 화면이 아니라 서버와 보안 규칙에서 한다.
- 관리자가 한 모든 변경은 누가, 언제, 무엇을 바꿨는지 기록하고 운영 일지에 남긴다.
- 관리자 화면에서도 사용자의 검색 문장과 재생목록 내용은 기본으로 보여 주지 않는다.

## 13. 제약과 원칙

- 음원과 영상 파일은 저장하지 않는다.
- YouTube 플레이어를 숨기거나 변형하지 않고, 광고를 막지 않는다.
- 이 앱이 만든 재생목록만 수정한다. 사용자의 기존 재생목록은 절대 바꾸지 않는다.
- 사용자의 YouTube 계정 권한은 재생목록을 만드는 데만 쓴다. 최소 권한만 요청하고, 연결 정보는 암호화해서 서버에만 둔다.
- 사용자는 자기 데이터만 읽고 쓴다.
- 할당량은 돈으로 살 수 없다. 프로젝트를 여러 개 만들어 합치거나 비공식 수집 도구를 쓰지 않는다.
- 검색창 입력과 외부에서 가져온 글에 들어 있는 지시문은 명령으로 취급하지 않는다.
- 위 항목 중 강제할 수 있는 것은 문서가 아니라 코드, 테스트, 훅, 보안 규칙으로 강제한다.

## 14. 호스팅

- Firebase: 호스팅, 로그인, 데이터 저장(Firestore), 예약 실행과 서버 코드(Cloud Functions).
- API 키와 비밀값은 서버 쪽에만 둔다.
- 데이터 접근은 보안 규칙으로 제한한다. 현황판 수치는 누구나 읽고 서버만 쓴다.
- 예산 알림을 설정한다.

## 15. 단계

| 단계 | 내용 |
|---|---|
| 1단계 | 기록, 곡 목록 수집, 핵심 흐름, 사이트 재생, YouTube에서 열기와 공유 주소, Google 로그인, 사용자별 한도, 한국어·영어, 약관, CI, 자동 수정 흐름, 현황판과 운영 일지, 관리자 화면, 배포, Google 앱 심사 신청 |
| 2단계 | 내 재생목록 보관함, 조건 지정(연도, 제외 아티스트, 분위기), 무한 재생, 심사 통과 후 "내 계정에 바로 넣기" 전체 공개, 할당량 증가 신청 |
| 3단계 | 공개 재생목록 수집(그 곡이 든 재생목록 찾기, 추천 재료로 활용), 공연 예습 재생목록, Spotify, 언어 추가 |

1단계가 크다. 만드는 순서는 "로그인 없이 동작하는 핵심 흐름 → 공개용 기능(로그인, 한도, 약관)"으로 나눈다.

## 16. 1단계 완료 기준

- 로그인한 사용자 누구나 자연어 요청으로 재생목록을 만들고 사이트에서 재생할 수 있다.
- 만든 재생목록을 YouTube에서 열거나 주소로 공유할 수 있다.
- 대부분의 요청이 YouTube 검색 호출 없이 처리된다.
- 곡 목록이 매일 밤 사람 손 없이 갱신된다.
- 일부러 넣은 오류 하나가 이슈 → 수정 PR → CI 통과 → 내 승인까지 진행된다.
- 한 사용자가 하루 한도를 넘겨도 다른 사용자는 영향을 받지 않는다.
- 다른 사용자의 데이터를 읽거나 바꿀 수 없다는 것을 테스트로 확인했다.
- 현황판에 실제 기록으로 계산한 수치와 운영 일지가 표시된다.
- 관리자 화면에서 긴급 정지를 켜면 재생목록 만들기가 즉시 멈춘다.
- 관리자가 아닌 계정은 관리자 화면과 관리자용 기능에 접근할 수 없다는 것을 테스트로 확인했다.
- 배포되어 주소로 접속할 수 있다.

## 17. 시작 전에 확인할 것

공식 문서로 확인하고, 이 기획서의 가정과 다르면 알린다.

- YouTube API: 호출 종류별 할당량, 채널 영상 목록을 받는 방법과 비용, 받은 데이터의 보관 기간과 갱신 조건
- YouTube 삽입 플레이어 정책, 공개 서비스가 지켜야 할 약관 항목
- 로그인 없이 여러 영상을 재생목록으로 여는 링크 방식이 동작하는지
- 사용자의 YouTube 계정에 재생목록을 만드는 권한과 Google 앱 심사: 조건, 준비물, 심사 전 사용자 수 제한
- 비슷한 곡, 장르, 태그를 주는 공개 음악 데이터와 이용 조건
- Firebase: 예약 실행과 외부 API 호출에 필요한 요금제, 무료 사용량
- 예상 비용: 사용자 한 명이 하루 한도만큼 썼을 때의 AI 비용과 YouTube 호출 수
